# Brand Voice -- Voice Configurator

> Часть курса [wayan-claude-md](../../README.md) от [Wayan Onchain](https://t.me/wayan_onchain).
> Трек: **CLAUDE PRO**. Обязательный скилл для контент-агента (см. [examples/marketer-pro-filled.md](../../examples/marketer-pro-filled.md)).

## Когда использовать

- Новый бренд / новый клиент -> впервые настроить голос
- Голос «уехал» (после правок / смены тона) -> переобучить
- Появилась обратная связь от ЦА (комменты, реакции) -> докинуть в few-shot
- Регулярная проверка раз в 1--2 месяца

## Что делает

1. Принимает 15--30 прошлых публикаций оператора (TG-посты, рилсы, рассылки, лонгриды)
2. Извлекает паттерны:
   - **Словарь** -- любимые слова, профессионализмы, отказные («не пиши: давайте, итак, кстати»)
   - **Длина предложений** -- средняя, медиана, разброс
   - **Структура** -- какой хук используется, какая концовка, как ставит CTA
   - **Эмодзи** -- использует / не использует / только в специфичных местах
   - **Кавычки** -- русские / английские / «`<<>>`»
   - **Тире** -- короткое / длинное / двойное (`--`)
   - **Тон** -- дружелюбный / экспертный / провокационный / премиум / эмоциональный
   - **Signature phrases** -- фирменные обороты, которые отличают автора
3. Генерирует `~/.claude/rules/voice.md` или `core/voice.md` (для конкретного workspace)
4. Возвращает один тест-пост в новом голосе, оператор апрувит

## Формат voice.md

```markdown
# Voice: {{BRAND_NAME}}

## Tone
- Главное: {{экспертный / дружелюбный / провокационный}}
- Подтон: {{тёплый / резкий / нейтральный}}
- Запрещено: {{официоз / излишняя эмоциональность}}

## Vocabulary

### Love (используй активно)
- {{слово 1}}
- {{слово 2}}
- {{профессионализм 1}}

### Hate (никогда не пиши)
- давайте
- итак
- кстати
- как видим
- хочу поделиться
- {{другие AI-штампы оператора}}

## Sentence structure
- Средняя длина: {{8--14}} слов
- Максимум: {{25}} слов
- Минимум: {{3}} слова
- Разрыв коротких/длинных: ритм через чередование

## Signature phrases
- {{«Главное -- ...»}}
- {{«Без воды:»}}
- {{«Это рабочее.»}}

## Format
- Кавычки: <<>>
- Тире: --
- Эмодзи: {{никогда / только в начале хука / только список}}
- Capitalization: {{Sentence case}}
```

## Процесс настройки

### Шаг 1: сбор материала

Оператор присылает 15--30 публикаций:
- 5--10 TG-постов (лучшие по охвату)
- 3--5 рилс-сценариев
- 2--3 email-рассылки
- 1--2 лонгрида (если есть)

Если у оператора нет 15 публикаций -- работай с тем, что есть, но честно скажи:
«Голос будет более общим, рекомендую переучить после набора 20+ публикаций».

### Шаг 2: анализ

Не угадывай. Считай.

- Длина предложений -- средняя и разброс
- Топ-30 слов -- ручной разбор оператором (что любит, что не любит)
- AI-штампы -- найди в анти-примерах ChatGPT и добавь в Hate-список
- Структура хуков -- разбери первые 7 слов 10 лучших постов

### Шаг 3: генерация voice.md

Пиши краткий voice.md (не больше 100 строк). Длинный голос = большой расход токенов
в каждой сессии (помни про правило 4 @includes из wayan_onchain).

### Шаг 4: тест

Напиши ОДИН пост в новом голосе. Сравни:
- Длина предложений в твоём посте vs средняя у оператора
- Использование запрещённых слов (должно быть 0)
- Использование signature phrases (должно быть 1--2)

### Шаг 5: апрув оператора

Покажи: voice.md + тест-пост + сравнение метрик.
Оператор: «зашло» -> сохраняй. «не зашло» -> что не так? -> повтор.

## Правила

- **Голос -- это файл, а не «вкус».** Если не описано в voice.md -- значит, агент не знает. Не угадывай
- **Считай, а не угадывай.** Длина, частотность, паттерны -- из реальных постов оператора
- **AI-штампы -- враг номер 1.** Любой текст, где есть «давайте поговорим о...» -- автоматически на переписать
- **Few-shot 3--5 примеров.** Меньше -- не научится. Больше -- не вмещается в @include
- **Versioning.** Каждое изменение voice.md = новая версия (`voice-v2.md`, `voice-v3.md`). История голоса важна
- **Раз в 2 месяца -- ревизия.** Голос «уезжает», аудитория меняется -- добавляй свежие примеры

## Integration с другими скиллами

- `self-compiler` -- собирает голос пассивно из обычных диалогов (если активирован)
- `present` -- использует voice.md для HTML-презентаций клиенту в правильном тоне
- `onboarding` (track=PRO) -- автоматически предлагает запустить brand-voice после первой настройки

## Файловая структура

```
~/.claude/
├── rules/
│   └── voice.md              # глобальный голос (твой личный)
└── projects/
    ├── client-bread/
    │   └── core/
    │       └── voice.md      # голос конкретного клиента
    ├── client-medlab/
    │   └── core/
    │       └── voice.md
    └── client-kids/
        └── core/
            └── voice.md
```

Для агентства (несколько клиентов) -- voice.md живёт **в Project каждого клиента**,
не в глобальном. Иначе агент перепутает голоса.

## Anti-patterns

| Делать | Не делать |
|---|---|
| 3--5 примеров в few-shot | 20 примеров -- слишком жирно |
| Считать длину предложений | «Пиши коротко» (агент не знает что коротко) |
| Hate-список конкретный | «Не пиши как ИИ» -- абстрактно |
| Versioning voice-v2, v3 | Перезапись поверх (теряется история) |
| Voice per client | Один общий voice на всех |
